0) Overview

Halaman ini dibuat dengan style yang konsisten dengan xweather_manual, tetapi fokus pada alur data produk IRIS.

IRIS Workflow

Secara sederhana, IRIS menghubungkan task radar, ingest data, RAW product, product configuration, product scheduler, lalu display / export / archive. Produk volume seperti CAPPI, MAX, TOPS, VIL, dan XSECT membutuhkan kumpulan elevasi dari volume scan, sedangkan beberapa produk lain bisa langsung berjalan dari task atau ingest yang sesuai.

Task-driven RAW as transport layer Scheduler-based generation Display + archive + export
TaskRadar melakukan measurement task dan menyimpan data ke ingest files.
RAWRAW menyimpan parameter sinyal mentah radar dan bisa dipindah untuk product generation.
ProductPPI, CAPPI, MAX, RAIN1, RAIN-N, SRI, TOPS, XSECT, dan lainnya dibangun dari task atau re-ingested RAW.

1) Flowchart – RAW Files to Final Product

Versi operasional yang bisa langsung dipahami oleh engineer, forecaster, atau developer.

End-to-End
1

Radar runs a task

Task dapat berupa PPI, full volume, sector, hybrid, atau task lain sesuai konfigurasi radar. Task inilah sumber awal seluruh produk.

2

Task writes ingest data

IRIS menyimpan hasil task sebagai ingest files. Product configuration kemudian akan mengaitkan produk dengan task yang sesuai.

3

RAW product packages measurement data

RAW menyimpan parameter mentah seperti Z, ZT, V, W, ZDR, dan lainnya dalam koordinat polar. RAW tidak ditampilkan langsung, tetapi penting untuk archive, transfer jaringan, dan re-processing.

4

Product configuration defines the derived product

Di tahap ini dipilih jenis produk seperti PPI, CAPPI, MAX, TOPS, RAIN1, RAIN-N, XSECT, atau produk lain, berikut data type, range, smoother, projection, dan resolution.

5

Scheduler decides when product is generated

Product Scheduler akan menjalankan produk saat data yang dibutuhkan tersedia. Untuk volume products, scheduler menunggu seluruh elevasi atau input terkait.

6

Generated product is displayed or exported

Hasil akhir bisa ditampilkan di Quick Look Window, dikirim ke output device, diarsipkan, atau diekspor ke format lain seperti HDF5, BUFR, atau NetCDF tergantung pipeline yang dipakai.

Practical note: RAW sangat berguna bila product generation ingin dipindah ke mesin lain, atau ketika Anda ingin melakukan post-processing / analysis tanpa membebani radar host utama.

2) RAW Layer – Why it matters

RAW bukan sekadar file arsip; ia adalah jembatan utama antara akuisisi dan reproduksi produk.

RAW
  • RAW dibuat satu-per-satu dari ingest files.
  • RAW menyimpan parameter signal processor dalam koordinat polar.
  • RAW dapat dikirim ke komputer IRIS Analysis lain untuk membangun produk tanpa memproses semuanya di radar host.
  • Saat RAW diterima kembali atau diretrieve dari archive, ingest file baru dibuat sehingga product generation bisa berjalan lagi.
Best use case
Transfer volume radar dari host produksi ke analysis node untuk generate CAPPI, MAX, XSECT, atau produk eksperimen.
Operational benefit
Mengurangi beban CPU radar host, terutama bila product mix banyak atau resolusi tinggi.
Development benefit
Memungkinkan testing produk baru, export converter, atau validasi algoritma tanpa mengganggu sistem utama.
Important caveat
RAW sendiri tidak langsung “displayable”; ia harus di-reingest atau diubah menjadi produk akhir terlebih dahulu.

3) Task + Product + Scheduler Relationship

Bagian ini yang biasanya paling penting untuk debugging kenapa produk belum muncul.

Scheduling Logic
A

Task association

Setiap product dihubungkan ke task tertentu. Produk volume seperti CAPPI, MAX, TOPS, VIL, XSECT, VVP, dan WIND membutuhkan multiple elevation angles.

B

Matched resolution matters

Bin spacing, jumlah bins, max range, dan output pixel resolution yang serasi akan memperbaiki performa dan tampilan produk.

C

Scheduler trigger

Product Scheduler menjalankan produk ketika input yang dibutuhkan sudah tersedia. Bila data belum lengkap, product bisa menunggu atau tidak jadi dihasilkan sesuai aturan scheduler.

D

Output handling

Setelah produk jadi, Output menu menentukan apakah hasilnya hanya tampil di display, dikirim ke device tertentu, atau disimpan ke archive / pipe converter.

4) Typical Product Paths

Contoh alur yang paling sering dipakai di operasional.

Examples
PPI path Task PPI → ingest → PPI configuration → scheduler → PPI display/output.
CAPPI path Volume task → ingest / RAW → CAPPI configuration → height interpolation → scheduler → CAPPI display.
MAX path Volume task → multiple elevations → CAPPI-like internal layer construction → MAX horizontal + side panels.
RAIN1 / RAIN-N Reflectivity / rain-rate inputs → accumulation logic → hourly or N-hour rainfall product.
XSECT Volume scan → user-definable line → height cross-section product.
Offline analysis RAW archive → reingest on IRIS Analysis → build products later for QA, testing, or R&D.

5) Output, Archive, and Export Converters

Setelah product final tersedia, langkah berikutnya adalah interoperability.

Outputs

IRIS Utilities menyediakan output pipes untuk berbagai format. Dalam banyak implementasi, ini menjadi titik integrasi ke sistem eksternal, archive nasional, atau workflow riset.

  • RAW dapat diekspor ke NetCDF.
  • Produk Cartesian tertentu seperti CAPPI, TOPS, MAX, RAIN1, dan lainnya dapat dikonversi ke BUFR, HDF5, atau format lain tergantung pipe yang diaktifkan.
  • Pipeline export biasanya diletakkan setelah product generation, bukan menggantikan product generation itu sendiri.
Recommendation: Untuk workload berat, gunakan strategi host produksi + analysis node. Radar host fokus ke akuisisi dan task kritikal, sementara analysis node fokus ke derived products, export, replay, dan eksperimen.
